# 对齐原版 · 7 个「部分实现」项推进清单

2026-10-19 起生效。范围：对比表里 7 个 🟡 项（原版有、本应用只做了一半的功能面）；
其余 29 个 ❌ 项与 1 个 ⛔ 项（VPN，有意不做）全部搁置。
对照基准：原版功能表 / Microsoft Store 文案 / luotopia-rea 逆向与实机记录。

## 清单（先做离线可验证的，后做需要实况会话的）

- [x] 1. 全校总课表：与我的课表冲突筛选（蹭课匹配）

      周次不可解析时记为「不确定」并从筛选结果剔除），总课表页新增「只看不冲突的课」开关与
      「可蹭课 / 与我的课表冲突」徽标；9 条单元测试 + 1 条界面冒烟测试；analyzer 与 585 测试全绿。
- [x] 2. 成绩：GPA 算法组、成绩趋势、多渠道导入
      — 2026-10-19 完成：`lib/features/grades_query/archive/` 本地成绩档案（教务读取自动归档、
      手工添加为第二条渠道，`source` 字段留给研究生系统等后续渠道）+ 三种算法（武大 4.0 表 /
      五分制线性 / 百分制加权均分，设置里持久化）+ 各学期趋势（自绘 bar，无新依赖）。
      详见 `docs/grades-and-reviews.md` §5.9；单元测试 36 条 + 界面测试 4 条；analyzer 与 625 测试全绿。
- [x] 3. 课程表与日程：多课表管理、周/月视图、重复规则、上课提醒
      — 2026-10-19 完成：多课表（`timetable.profiles` + 每表独立课程文档，旧的单表布局自动迁移）、
      真正的周网格（7 天 × 12 节，课程块跨节、按名字稳定配色）与月视图（课 + 日程同屏）、
      日程重复规则（每天/每周/每月 + 截止日）、上课提醒（首页「下一节课」倒计时 + 开课前 15 分钟
      应用内提示；**不做系统通知**，课程无上课时间时不猜时间）。详见 `docs/timetable-and-map.md`。
- [x] 4. 校园地图：原生地图 + 设施图层
      — 2026-10-19 完成：332 个真实设施点从 OpenStreetMap 抓取后内置（ODbL 署名在图上），
      自绘地图 + 拖动缩放 + 六类图层筛选 + 搜索 + 点选详情 + OSM 链接；原 Nominatim 搜索保留为第二页。
      详见 `docs/timetable-and-map.md`。
- [x] 5. 课程表多源导入（本科教务 N2151 / 研究生系统）
      — 2026-10-19 完成：N2151 解析器（`kbList`、`jcs`、`zcd` 的单双周/多段周、`qsjsj/jssj`）、
      会话内 POST 读取、预览与覆盖确认；同一门课的多段周次自动合并。**研究生系统渠道未实现**：
      没有研究生账号会话就无法取得其接口契约，界面上如实标为不可用。
      — 2026-10-20 实况修订：N2151 的数据端点现在对未经页面验证的请求返回空 `kbList`
      （页面要求先点「查询」并完成滑块验证），直接 POST 读不到课程。因此改为
      **在应用内浏览器打开课表页 → 本人完成滑块 → 读取页面已渲染的列表**
      （`lib/features/timetable/import/jwgl_timetable_browser.dart` +
      `jwgl_timetable_page_parser.dart`）；实况读到 20 门课、覆盖当前课表成功
      （2026-2027 第 1 学期，第一周锚点 2026-09-07 保持不变）。解析规则已在本校实况核对。
      原 18 条单元测试 + 新增 5 条页面解析测试。
- [x] 6. 学业状态原生页（现仅浏览器形态）
      — 2026-10-19 完成：`学业状态` 原生页从本地成绩档案算 GPA、已通过/总学分、必修/选修/其他
      学分构成、各学期学分与 GPA、不及格课程；毕业学分要求由用户设定，未设定时不画进度条
      （不编造要求）。入口在「更多」。8 条单元测试 + 2 条界面测试。
- [x] 7. 课程给分与评价：提交成绩 / 写评价
      — 2026-10-19 完成并实况核对：
      · **给分读取（Ham）**：本机已有 30 天令牌（2026-10-17 获取 / 2026-11-16 到期），
        `tools/list` 返回 13 个工具；直接查询「高等数学A1」返回 10 个教学班
        （均分 84.42 / 中位数 87 / 373 人），仓库的模糊名解析合并后实况为 27 个教学班。
        应用使用其中「给分统计 + 课程名解析」两个工具。
      · **评教入口**：按落地页自己的 JS 实现 `POST /loginSSO {userId}` → `forwardURL`
        （7 条 MockClient 测试），解析出的入口可在内置浏览器打开；新增「评价草稿」
        （本地写、复制、删除，14 条测试），评教时粘贴提交。
        — 2026-10-20 实况修订：只带中央票据 POST `/loginSSO` 会拿到**相对路径**的
        `forwardURL`，旧代码因此报「not an http(s) URL」。现在先按落地页的路径
        走一遍 CAS 握手（`getFollowing` 到 `ugsqs.whu.edu.cn/caslogin/`），用这一跳
        建立的会话 cookie 再 POST，并把相对路径按站点 origin 解析。
        实况解析结果：`ugsqs.whu.edu.cn/studentpj`（4 条 URL 解析单元测试）。
      · **我的 Ham（2026-10-20 增补，只读）**：接入 `get_user_info`、`get_score_rank`、
        `get_course_want_list`、`get_my_comments`、`get_course_comments`、
        `get_semester_grade_stats`；课程卡可点开看评论与学期统计。实况验证：用户信息 ok、
        高等数学A1 评论 8/8、2025-1 学期统计（均分 91 / 中位数 92 / 41 人 / 6 段）；
        该账号的排名/想上/我的评价为空（界面显示空态）。`get_course_detail` 两个变体
        需要网页登录态（返回「请重新登录」），不使用；`create/remove_course_want` 未接（写操作）。
      · **仍不可用（接口缺口，不是代码缺口）**：原版的 `submit_grade` / `create_review`
        是 **Luotopia 自己的后端**操作（其数据为空、需其账号），Ham MCP 的 13 个工具里
        没有提交成绩或写评论的工具；评教表单契约从未捕获，仍需人工填写提交。界面如实写明。

## 外部依赖（需要用户动作，解锁被阻塞项）

- **一次账户登录**：设置 → 账户登录 → 在应用内浏览器完成 CAS 登录（按页面要求过滑块/短信/OTP/扫码）
  → 点右上角钥匙「设为应用会话」。用于实况复跑：成绩链、N2151 课表导入、`POST /loginSSO` 评教入口、
  学业情况页对照。
- ~~Ham API Key~~ **已具备**：30 天令牌（2026-11-16 到期），给分读取已实况跑通；
  到期后在 Ham 控制台重新授权即可。写入（提交成绩 / 写评价）不因 Key 而可用：
  Ham MCP 的 13 个工具里没有这两类工具。
- **一次研究生账号会话**：解锁 #5 的研究生系统渠道（当前只有占位说明）。

## 约束（不变）

- 不代解滑块；凭据只走环境变量；应用设置里一次登录解锁全部功能。
- 本文件只记状态；证据与实况记录写到 `docs/grades-and-reviews.md` 对应章节。
